# Simplified Chinese locale pack — design and review report

**Date:** 2026-11-14 · **Scope:** `data/i18n/zh-Hans/` · **Base commit:** `d4440e2` ("Integrate Ontario and India primary curriculum coverage (#160)")

## 1. Outcome

The taxonomy now ships a complete Simplified Chinese locale pack. The English
data files are untouched: `data/topics.json`, `data/dependencies.json`,
`data/clusters.json` and `data/teaching-research.json` keep the same bytes,
the same checksums and the same ids. The Chinese text lives in a parallel pack
under `data/i18n/zh-Hans/`, joined to the graph by id.

| Surface | Rows | Chinese |
|---|---:|---|
| Topics (name, description, mastery evidence, assessment prompt) | 1,912 | translated |
| Domain summaries (cluster summaries) | 177 | translated |
| Prerequisite edges (reasons) | 4,002 | translated |
| Teaching-research records (pedagogy, learning activities, assessment prose, source claims) | 1,097 | 618 translated, 479 pending |
| Release notes | 6 | translated |
| Subject, domain, type, curriculum, method and error-kind labels | 12 / 74 / 5 / 21 / 5 / 5 | translated |

The teaching-research layer declares its own coverage, the same way the
English research export declares its gaps: `data/i18n/zh-Hans/teaching-research.json`
carries a `coverage` block with `topicCount`, `withTranslation` and
`pendingTopicIds`, and the validator checks that the declared gap is exactly
the real gap. A pack can therefore never look complete when it is not. The
translation of the remaining records continues in the background and each
merged pack states its own coverage.

Curriculum standard text is **not** translated. `data/curriculum-standards.json`
holds third-party framework wording under its own upstream licence, so the
graph keeps carrying codes only; a translation of that wording would exceed
what Marble may redistribute.

## 2. Why a parallel pack, not in-place fields

The alternative was to add `nameZh` / `descriptionZh` to `data/topics.json`.
It was rejected for four reasons:

1. **The English file is the published artefact.** Rewriting a 2.8 MB file
   with 12,000 added fields changes every checksum, every downstream cache
   key and every consumer's parse path for no graph-level benefit.
2. **The graph must stay single-sourced.** A locale pack holds prose only.
   Every id, edge, standard code, assessment method and error kind is copied
   from the English record at merge time, so a translation cannot introduce a
   node, an edge or a code that the English dataset does not have.
3. **Coverage becomes measurable.** A language is either translated or it is
   not; `npm run i18n:check` reports the exact missing rows.
4. **Languages do not block each other.** A second locale is a second
   directory; the English files are never a merge conflict.

## 3. What a locale pack contains

```
data/i18n/zh-Hans/topics.json            # id, name, description, evidence[], assessmentPrompt
data/i18n/zh-Hans/clusters.json          # subject, domain, ageRangeStart, summary
data/i18n/zh-Hans/dependencies.json      # topicId, prerequisiteId, reason
data/i18n/zh-Hans/teaching-research.json # topicId, prose, and the restored identifiers
data/i18n/zh-Hans/labels.json            # subject, domain, type, curriculum and enum labels
data/i18n/zh-Hans/notes.json             # the release notes of the research export
data/i18n/zh-Hans/manifest.json          # counts and SHA-256 checksums
```

Join keys: `topic.id`, `topicId`, `prerequisiteId`, and
`(subject, domain, ageRangeStart)` for a domain summary. The research record
keeps the English `method`, `kind`, `reteachPrerequisiteId`, `source`, `url`,
`verified` and `confidence` values, and each activity's `sourceClaims` is
derived from the translated `sources[].claim` it quotes, so the two lists
cannot drift apart.

## 4. Method

* **Shards.** `npm run i18n:shards zh-Hans` splits the English dataset into
  462 deterministic shards (34 topics, 2 clusters, 16 dependencies,
  410 research), each capped at about 55,000 source characters.
* **Glossary first.** Every translator reads
  [`docs/i18n/glossary.zh-Hans.md`](../docs/i18n/glossary.zh-Hans.md) before
  translating: 190+ agreed terms, the 26 high-risk English polysemes and the
  list of content that must survive verbatim.
* **Parallel translation.** Shards were translated independently, each by an
  agent that may only write its own output file, then self-verified with
  `npm run i18n:verify <shard>`. Four concurrent translators is what the
  machine sustains: at eight the children starve each other and fail, and a
  single translator is four times slower. A workflow stays reliable for
  roughly a dozen children, so the run proceeds in small batches and the
  outstanding work is reported by `npm run i18n:resume`. The run is resumable — a shard
  whose output is missing or fails verification is simply retried, and
  `npm run i18n:resume` reports what is outstanding.
* **Deterministic merge.** `npm run i18n:merge zh-Hans` rebuilds the pack from
  the English dataset plus the translated shards, re-attaching every
  identifier, and normalises Chinese typography (full-width quotation marks)
  in one place so the pack does not depend on individual translators.
* **Application build.** `npm run i18n:build zh-Hans` publishes
  `dist/zh-Hans/`, where every translated field carries the Chinese text and
  the English original stays beside it in a `<field>En` companion.

## 5. Validation

`npm run i18n:check` (also run by `npm run validate`, so CI enforces it)
rejects a locale pack that:

* misses a topic, cluster, dependency edge or research record, or invents an
  id that the English dataset does not have;
* changes a curriculum code, an assessment method, an error kind, a
  prerequisite id, a url, a source name or a confidence value;
* changes the length of a parallel array or the number of `{{name}}`
  placeholders;
* leaves a string without Chinese characters, or leaves a long English
  sentence untranslated;
* translates a string to an implausible length (below 0.12× or above 4× the
  English, for English text of 20 characters or more);
* does not match the checksums in `data/i18n/zh-Hans/manifest.json` and
  `data/manifest.json`.

## 6. Terminology decisions

The glossary resolves the English words that a literal translation would
mistranslate. The ones that mattered most:

| English | Chinese | Why |
|---|---|---|
| volume (sound) | 音量 | 体积 is the geometric volume; the sound sense is 响度/音量 |
| volume (geometry) | 体积 | and 容积 for a container's capacity |
| work (physics / maths) | 做功 / 运算 | 工作 is neither |
| key (map / answer / keyboard) | 图例 / 要点 / 键盘 | 关键 is wrong in all three |
| mean / mode | 平均数 / 众数 | the statistical senses |
| scale (ruler / map) | 刻度 / 比例尺 | 规模 is wrong in both |
| force / light / plant | 力 / 光 / 植物 | the common noun senses mislead in science |
| pitch / loudness | 音高 / 响度（音量） | the two variables the science topics separate |
| phonics | 自然拼读 | not 语音学 |
| Tier A / B / C | A 级 / B 级 / C 级 | the concreteness ladder of the research records |

`npm run i18n:term-audit` reports any string where an agreed term is missing
and shows how the polysemous words were resolved per subject.

## 7. Known limits

* **A translation, not a re-review.** The Chinese text restates the English
  claims. It does not re-verify the research, and it does not certify the
  linked curriculum standards.
* **The teaching-research layer is still being translated.** The topics,
  domain summaries and prerequisite reasons are complete; the research
  records are translated as the run proceeds, and the pack declares the
  exact gap. A consumer that needs a research record for a topic outside the
  translated set must fall back to the English file until the pack's
  `coverage.pendingTopicIds` is empty.
* **One finding in the English source.** The teaching-research record
  `mt_14T5yPXUq_` still states "2/3 + 5/4 is more than 2" in one
  learner-facing string, while the same record's `reviewNotes` and
  `constraints` record the correction (the sum is 23/12 ≈ 1.92, so the valid
  benchmark is "more than 1"). The Chinese follows the record's own
  corrected reading, which is recorded in the Chinese release notes; the
  English string itself is left for the English maintainers to fix.
* **Coverage of the Chinese curriculum is not claimed.** The pack translates
  the existing taxonomy; it does not add 义务教育课程标准（2022年版）or any
  other Chinese framework as a new curriculum source. That is separate
  ingestion work under the usual contract.
* **English source wording stays English.** Where a record quotes a
  curriculum standard, the Chinese quotes the translation of that wording and
  keeps the reference code; codes-only passages stay marked as omitted.
* **Regional vocabulary.** The pack uses mainland Simplified Chinese
  (大陆简体中文) wording, following the 术语表. Traditional-character and
  other regional variants would be a separate locale.

## 8. Re-running the translation

```sh
npm run i18n:shards zh-Hans     # deterministic shard plan
npm run i18n:merge zh-Hans      # rebuild data/i18n/zh-Hans/ from the shards
npm run i18n:check              # completeness, fidelity and translation checks
npm run i18n:build zh-Hans      # dist/zh-Hans/ for applications
```

After changing the English dataset, re-run `npm run i18n:check`: a locale
pack that no longer matches its source fails `npm run validate`, the same way
a broken edge does.

## 9. Validation results

`npm run validate`, `npm run alignments:generated-check` and `npm test` (the
repository's CI sequence) all pass with the locale pack in place, and the
English data files show no diff. The suite covers the pipeline itself: a
complete pack passes, a missing translation fails, a changed curriculum code
fails, an altered array length fails, an untranslated string fails, and a
research record may be absent only when the pack declares it as pending.
