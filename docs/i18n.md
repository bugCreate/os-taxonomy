# Localisation (i18n)

The taxonomy is published in English. A **locale pack** adds one language
without touching the English data files: the English graph stays the single
source of truth for ids, edges and curriculum codes, and the locale pack
carries the translated prose beside the identifiers it belongs to.

```
data/i18n/zh-Hans/topics.json            # 知识点名称/描述/证据/评估提示
data/i18n/zh-Hans/clusters.json          # 领域概览
data/i18n/zh-Hans/dependencies.json      # 依赖理由
data/i18n/zh-Hans/teaching-research.json # 教学研究（教学法/学习活动/评测）
data/i18n/zh-Hans/labels.json            # 学科、领域、类型等标签
data/i18n/zh-Hans/manifest.json          # 语言包清单与校验和
```

Chinese versions of this page: [docs/i18n.zh-Hans.md](i18n.zh-Hans.md).
Terminology: [docs/i18n/glossary.zh-Hans.md](i18n/glossary.zh-Hans.md).

## Why a parallel pack

* **The English files stay byte-identical.** Topic ids, prerequisite edges,
  curriculum codes and the manifest checksums of `data/topics.json` and
  friends do not move, so every downstream consumer keeps working unchanged.
* **A consumer joins by id.** `topic.id`, `topicId`, `prerequisiteId` and the
  `(subject, domain, ageRangeStart)` cluster key are the join keys. Nothing
  else may be used to match a translation to its source.
* **Coverage is measurable.** A locale pack is complete or it is not; the
  validator reports exactly which rows are missing.
* **One language cannot block another.** A new locale is a new directory.

## What is translated

| Field | Translated | Note |
|---|---|---|
| `topic.name`, `topic.description`, `topic.evidence[]`, `topic.assessmentPrompt` | yes | `assessmentPrompt` keeps its `{{name}}` placeholder |
| `cluster.summary` | yes | matched on subject + domain + age band |
| `dependency.reason` | yes | matched on topicId + prerequisiteId |
| `teaching-research` prose | yes | pedagogy, learn activities, assessment prose, source claims |
| `subject`, `domain`, `type`, `strength`, `method`, `kind`, `confidence` | no | stable keys; the Chinese wording lives in `labels.json` |
| topic ids, curriculum codes, urls, publication names | no | must survive verbatim |
| `data/curriculum-standards.json` | no | external curriculum text keeps its upstream licence terms |
| record `schemaVersion`, `namespace`, `authorship`, activity `id`, activity `sourceIds`, error-pattern `id`, source `id` | no | identifiers of the v2 research schema; copied from the English record |

The research layer follows the canonical v2 shape in
`schema/canonical-teaching-research-v2.schema.json`: a record carries its
`schemaVersion`, its `namespace` and its `authorship`, every activity carries
an `id` and the `sourceIds` it rests on, every error pattern carries a
`diagnostic_` id and every source a `citation_` id. Those are identifiers,
not prose: the merge copies them from the English record, so a translation
can never renumber an activity or point at a citation that does not exist.

## Validation

`scripts/check-i18n.mjs` is the gate. It refuses a locale pack that:

* misses a topic, cluster, dependency edge or research record, or invents an id
  that the English dataset does not have;
* changes a curriculum code, an assessment method, an error kind, a
  prerequisite id, a url or a confidence value;
* changes an identifier of the v2 research schema — the record version or
  namespace, the authorship, an activity id, the citation ids an activity
  rests on, a diagnostic id or a citation id;
* changes the length of a parallel array, or the number of `{{name}}`
  placeholders;
* leaves a string without Chinese characters, or leaves a long English
  sentence untranslated;
* translates a string to an implausible length (below 0.2× or above 3× the
  English source);
* does not match the checksums recorded in `data/i18n/<locale>/manifest.json`
  and `data/manifest.json`.

`npm run validate` runs the check for every locale pack it finds, so a broken
translation fails the same way a broken edge does.

## Coverage of the research layer

The research layer mirrors the English export record for record, and it
declares its own coverage in `coverage`:

```json
"coverage": { "topicCount": 1912, "withTranslation": 1097, "pendingTopicIds": [] }
```

`topicCount` is the number of records in the English export, `withTranslation`
the number of records the pack carries, and `pendingTopicIds` the records that
are still waiting for a translator — exactly the set of English records the
pack does not have. A record may be absent only when it is declared pending,
so the coverage block can never hide a gap. `npm run i18n:check` recomputes
both numbers and fails when they disagree.

## Commands

```sh
npm run i18n:shards zh-Hans     # split the English dataset into work shards
npm run i18n:merge zh-Hans      # join translated shards into the locale pack
npm run i18n:check              # validate every locale pack
npm run i18n:build zh-Hans      # publish dist/zh-Hans/ for applications
npm run i18n:test               # unit tests for the checks and the build
```

`npm run i18n:build` writes `dist/<locale>/`, where every translated field
carries the localized text and the English original stays in a `<field>En`
companion. A consumer can then switch languages from one file.

## Adding a locale

1. `npm run i18n:shards <locale>` — writes `work/i18n/shards/*.json` and the
   plan in `work/i18n/plan.json`.
2. Translate each shard into `work/i18n/out/<shard>.json`. The output is a
   JSON array with the same rows, in the same order, with the same keys.
3. `npm run i18n:merge <locale>` — writes `data/i18n/<locale>/` and refreshes
   `data/manifest.json`.
4. Author `data/i18n/<locale>/labels.json` (subjects, domains, types) and a
   glossary under `docs/i18n/`.
5. `npm run i18n:check && npm run validate && npm test`.

The translated text is a derivative of Marble's own ODbL 1.0 + CC BY-SA 4.0
work, so a locale pack is published under the same terms with the same
attribution. Curriculum standard text is **not** translated: it stays in
`data/curriculum-standards.json` under its upstream licence, and only codes
